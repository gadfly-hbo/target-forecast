## 1. 本次要交付的产品

帮助零售经营负责人、运营及分析人员，把一个经营期待变成有数据、有假设、可比较、可保存、可复查的测算方案。

主流程：**说明目标 → 准备数据 → 形成并调整假设 → 计算比较 → 保存方案与运行 → 导出同一次结果。**

目标测算先完整贯通。优惠券与 ROI 保留原功能，待这一流程稳定后，再复用方案、运行、导出和 AI 修改机制。原仓继续独立可运行；本轮不预设 JuanerAI 接入，不改其他工具或共享 SDK。

产品承诺：页面、手动操作、AI 工具、CLI 和报告读取同一个明确的方案或运行身份。工作稿可变，保存的运行不随工作稿改变。计算结果是给定假设下的情景推演，不承诺统计预测准确性，不自动批准经营行动。

## 2. 用户与第一版边界

- 主用户：能解释业务目标，手里有订单或汇总报表，但不应被要求理解 API、JSON 或引擎字段名的经营人员。
- 专业协作者：确认数据口径、补齐输入、调整假设依据的分析人员。
- 第一版部署：个人本地，单个工作空间；支持方案重开，不引入账号、企业权限或多人协作。

- 暂不包含：自动抓取平台数据、执行投放、券投放、真实资源优化、因果识别、通用 Agent 平台、自动经营决策。

### 4.1 从自然语言开始

首页仅要求用户描述业务期待，不先填写专业参数问卷。真实实现中，AI 提取目的、指标、范围、期间和约束，形成带未决项的草稿。不明确的目标数字、平台或口径保持待确认，不自动把演示默认值当业务事实。

允许完全不用 AI：用户直接创建并编辑目标，导入数据，手动设定假设。AI 未配置或失败不影响这条主流程。

demo 使用固定 2027 年预置方案展示上述流程，保留输入的业务描述，并在首页标明预置与模拟边界。它不声称任意文本已被模型理解。

### 4.2 数据准备

正式版保留两种输入：订单明细（模式 A）、平台月度指标（模式 B）。在界面选择文件并预览映射，不再要求用户手工放到源码目录。保留目录／CLI 输入兼容路径，但都生成同一种数据快照。

计算前最少检查：必需字段、有效日期／月份、有限数值、金额范围、平台＋月份唯一性、期间覆盖、同平台 A/B 冲突、订单身份一致性、退款净额口径、零总量。异常应定位到文件／行／列，不能仅返回 HTTP 500。

同平台 A/B 冲突必须让用户选择来源，不允许后读文件覆盖前读文件。多平台必须落在共同基期和共同目标期；需要缩短范围或排除平台时由用户确认。演示／业务来源随数据快照持久保存，重启不改变身份。

无 UV 时场视角显示"缺少流量数据，未启用"，人视角仍可运行；不编造 UV，不把缺失字段的计算当 0。

demo 支持样例加载与 CSV 粘贴检查：`平台,月份,新客GMV,老客GMV`，金额单位为元，2026 年每个平台 12 个月。CSV 是审核用的缩小输入面，不代替正式版两种 XLSX 导入。

### 4.3 假设形成与人工判断

每项假设要有值、来源类型、解释、适用范围和待验证事项。首版以人视角核心驱动为主，场／货驱动在数据足够时显示；无效参数不显示成可生效输入。

默认三档不代表推荐顺序。历史变化可以提供参考，不能自动推出未来增长率。AI 可解释驱动、生成候选假设和列出缺口，用户负责接受关键假设。

手动保存与 AI 采纳走同一个更新入口。AI 提案需展示旧值、新值、影响范围及会失效的确认；放弃零变更；提案基于旧修订时拒绝覆盖，要求重新生成。小修改无需调用模型。

"确认用于试算"只承认当前假设可用于本次条件推演。不能将 `business_input` 或 AI 建议提升为经过实验验证的事实。数据、口径、计算相关假设改变后，相关确认失效。

### 4.4 计算、比较与保存

计算请求冻结当前输入，异步状态至少区分：准备不足、计算中、已完成、失败、已取消、执行结果未知。计算失败保留工作稿和旧运行；停止生成或计算不写入半结果。若算完时工作稿已改变，结果关联原修订并明确提示，不覆盖最新工作稿。

结果比较展示：各档净 GMV、较基期变化、距经营期待差距、月度分布、平台贡献和人／货／场一致性。比率分子分母必须来自同一视角和覆盖范围。交叉校验阈值可以告警，不能证明正确性。

用户选择讨论情景后点击"保存方案与本次运行"，固定输入及三档结果；版本名称对用户简单，例如 v1.0；内部的 schema 与 ID 规则留工程设计。

同内容重复保存返回已有版本／运行，避免无意义重复。显式重新运行若引擎或数据发生变化，是新输入身份；不通过覆盖旧结果实现"升级"。

工作稿变更后，旧结果仍可阅读和导出，但明确显示来自旧版本。当前工作稿的"保存结果"被阻断直到重新计算。旧记录不删除、不重算冒充原结果。

### 4.5 导出与继续工作

正式版保留目标 Excel 报告和中间指标 CSV；增加输入与参数来源、方案版本、运行时间和计算口径。报告与页面统一读取保存的运行快照，不能下载全局固定文件名指向的上一次 CLI 产物。

导出失败显示"运行已保存，导出失败可重试"，不能撤销已保存运行或声称未保存。重试只读指定运行，不重新计算。重开工作空间能恢复工作稿、版本和运行。

demo 真正下载 HTML 报告、月度 CSV、JSON 快照，三者来自指定运行。HTML 可浏览器打印为 PDF；不伪称 Excel 已接入。

## 5. 最小领域对象与状态约束

| 对象 | 保存什么 | 可变性与关系 |
|---|---|---|
| 方案工作稿 | 目标、范围、数据引用、口径、情景假设、采用档、待确认项 | 一个持续可修改的业务对象；手动和 AI 共用；每次变更增加修订 |
| 数据快照 | 来源、内容身份、映射、平台／期间、质量检查、演示标记 | 被运行引用后不可原地变更；替换生成新快照 |
| AI 修改提案 | 基于的修订、字段差异、影响和理由 | 待采纳／已采纳／放弃／已过期；不持有另一份业务参数库 |
| 方案版本 | 明确一次业务设计及其假设和数据引用 | 不可变；由工作稿显式保存得到 |
| 运行记录 | 完整输入身份、引擎版本、状态、结果、告警和时间 | 成功结果不可变；失败不假装业务成功；关联精确方案版本 |
| 导出产物 | 来源运行、格式、内容摘要和生成信息 | 从指定运行生成；不跟随工作稿 |

状态不是单个"大绿灯"。需要分别显示：工作稿已保存、口径已确认、假设已确认、计算完成、运行已保存、文件已导出。

建议的首版存储仍为本地文件，避免为了版本管理先引入数据库。要求原子写、内容身份、冲突检测和重开可读。具体文件组织、索引结构、公共 schema 与迁移协议在方案审核后设计，不在 UI demo 中冒充生产合同。

## 6. 技术重构路径：围绕现有实现逐段替换

### 阶段 A：先收敛可信计算与真实依赖

保留 `target_forecast/engine.py`、`ingest_*`、`pipeline.py`、`aggregate.py` 和报告模块的边界。

优先验证与修正：全无 UV 缺列、SKU 梯队索引错配、短历史年化、平台时间覆盖、同名 A/B 覆盖、聚合数值校验、混合视角分母。以合成最小数据固定业务期望，不用历史输出指纹把错误锁成标准。

固定 Pi 实际版本及适配接口；当前 `file:../../pi-agent-runtime` 软链接已指向 0.5.3-harness.3，与 0.4.3 验收叙述不同。先验证现有能力再决定升级或固定，不修改共享仓来迁就本产品。

验收：不改变业务假设的正常案例保持预期结果；异常样本返回可处理问题；真实依赖身份可解释。

### 阶段 B：引入一份方案、一次运行

在业务层增加最小的方案更新、数据快照、计算与运行存储能力。工具页、CLI 和助手调用这一层，避免重复写入／合并逻辑。先完成手动主流程，再接 AI。

复用现有流水线和报告生成器；报告从运行快照构造，去掉"读最近一次 output 文件"作为当前结果交付的路径。原旧报表仍可作为明确标记的旧产物下载，不冒认成新运行。

验收：同一方案手动改参、保存、关闭重开、生成报告，输入与结果一致；修改工作稿不改变历史文件。

### 阶段 C：按本次审核通过的 demo 落 UI

沿用现有轻量前端形态即可，不把框架迁移设为前置。页面重构为稳定 shell＋五工作视图＋上下文助手；JSON API 承接真实方案与运行。

正式实现应保留审核通过的布局、弹窗、交互反馈、键盘和窄屏行为。可以替换数据层和后端接线，不能因为原型标了"演示"就把已审核弹窗改成另一套流程。

验收：按下方 A01—A15 可观察行为走通；保存和导出由真实引擎与存储支撑。

### 阶段 D：将 AI 接到同一更新入口

只向 AI 提供当前方案修订、有效参数、质量问题和所需结果摘要；需要获取数据时通过受限业务工具读取，不把原始订单默认外发。

读能力：读取有效方案、检查缺口、试算、比较指定运行。写能力：提出补丁、采纳已确认补丁。绑定方案、修订、动作与参数内容；执行点校验提案一致性、确认状态与幂等身份。恢复结果未知时先读回状态，不用盲目重复执行兜底。

Pi 负责通用模型循环、调用与计量；业务对象、规则、确认和保存归产品。Pi 类型留在适配层。无 AI 时手动流程照常。

验收：AI 建议采纳后手动视图立即一致；拒绝零变更；过期提案拒绝；超时／恢复／重复确认不重复写；对话不重载页面丢失工作稿。

### 阶段 E：在第二个真实工具上验证复用

优惠券先复用方案／运行／导出身份和提案应用流程，保留其分支账本、约束、证据等级及复盘语义。ROI 再加入持久计划与运行。只抽取两处真实共用的机制，不先建设通用插件平台。

## 7. 已有数据与兼容策略

- `config.yaml` 是旧默认参数来源，不再成为多处隐式当前状态。首次打开提供"从现有配置创建方案"，记录来源。
- `workspace/forecast/orders|metrics` 作为用户选择的旧输入来源读取，不自动改名、删除或覆盖；形成数据快照后运行引用固定内容。
- `assistant_params.json` 若存在，预览与默认参数的合并差异，用户确认后纳入新工作稿；冲突或未知字段列明，不静默吞掉。
- 旧 Excel／CSV 标为"旧版产物，未关联新运行"，不伪造历史输入和版本链。
- 新旧入口可并行一个过渡期，但新增方案与运行不能由旧代码直接覆盖。迁移前备份，出现失败保留原文件与问题清单。
- 删除旧路径必须以新路径覆盖和回归证据为前提，不把首轮重构写成全仓重写。

## 8. UI 规范与交互契约

表面类型：经营测算工作区；默认 balanced，表格 compact，首页 comfortable。主信息顺序：当前方案与状态 → 当步主任务 → 结果／输入 → 下一步。右栏辅助而不替代工作区。

亮色沿用 metric-factory：canvas `#f6f7f4`，surface `#fcfcfa`，sidebar `#f0f2ed`，正文 `#36443f`，主色 `#27664f`，边框 `#dce2d9`。暗色使用对应语义 token；不简单反色。正文 14px、元信息 12px、标题 24px；系统中文字体；控件 6px、面板 8px 圆角。

桌面：230px 左栏、64px 顶栏、主工作区＋286px 助手。宽度不足 1200px 助手置于主要内容之后；900px 下导航收合；390px 表格在自身容器横向滚动，页面不横向溢出。

交互：原生按钮／表单／dialog；可见焦点、skip-link、Esc 关闭、弹窗关闭后焦点返回；长中文不撑破容器；加载、失败、取消、禁用、选中和确认失效状态可见。动画尊重 reduced-motion。

错误必须保留用户输入并解释怎么继续。未保存表单离开时保护内容，不能因提案或问答刷新丢失。

原型与正式实现的边界：
- 应沿用的用户交互：页面结构、编辑和提案方式、确认位置、状态语义、结果比较、保存和指定运行导出。
- 需要替换的演示实现：预置草稿、规则模拟 AI、简化计算、浏览器 localStorage、演示 CSV、HTML 报告。
- 正式实现新增但必须映射到可见状态：真实文件导入、业务引擎、磁盘快照、真实 AI、恢复／导出错误。

## 10. 建议本轮审核的三个重点

1. 首页和五个工作视图，是否足够贴近你制定经营目标的顺序；是否需要将"数据准备"与"目标理解"并列为两种起点。
