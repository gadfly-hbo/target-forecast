# Red-Team: 优惠券测算工具 v2.0 P0（独立产品方案 → 本地测算工具）

评估对象：`.flow/proposal.md`（固定自用户附件《优惠券测算工具_v2.0_独立产品方案.md》）。
评估方式：公式级独立复算（/tmp 一次性脚本，未改动项目文件）。

## Top Kill-Assumptions (ranked)

### 1. 文档公式与第七节黄金数值不对应（致命 · 已检验 · 被证伪，规格成立）

- **Claim**：按 4.2–4.5 字面公式实现可复现第七节全部黄金数值（M20/黄金案例是验收基石）。
- **Fails if**：字面公式与黄金表数值不一致且无法判断哪边为准（配套自检脚本 `优惠券测算工具_v2.0_模型自检.py` 未随附件提供，无法对照参考实现）。
- **检验结果（本次已完成）**：用独立脚本按字面公式复算——基准表 9 行（转化率/商家券补/总贡献/ΔΠ）+ 压力表 6 项**全部精确匹配到分**（容差 0.005 元）。中途出现的偏差是复算脚本自身 bug（流失分支误计正毛利），修正后完全一致。**结论：规格内部自洽，黄金值可直接作为引擎验收黄金测试。**
- **Kill criterion**：若后续引擎实现用整数分口径无法在 ±0.01 元内复现，以公式为准并排查实现，不反向改黄金值。

### 2. P0 范围超出单次 flow 预算（影响高 · 概率中 · 需在拆解时控制）

- **Claim**：数据导入 + 场景配置 + 四子模型引擎 + 比较决策 + 敏感性/盈亏平衡 + 三格式导出 + 复盘 + 快照重跑 + 四页面 UI + M01–M20 验收可在预算内交付。
- **Fails if**：不按 tracer-bullet 纵切、试图先把某层做全（尤其先做 UI 或先做完整存储层）。
- **Evidence to get this week**：拆解后的 slice 数量与依赖图（本 flow ISSUES 阶段产出）。
- **Kill criterion**：实现阶段消耗预算 2/3 仍未进入 UI slice → 将 UI 降级为单文件多页签最小工作台，复盘页并入历史页签。
- **Cheapest test**：拆解时按「引擎黄金案例 → 约束/敏感性 → 导入/导出 → 快照重跑 → UI」排序，每个 slice 独立可验收。

### 3. 行为参数面过宽，用户填不出/乱填（影响中 · 概率未知 · P0 后风险）

- **Claim**：业务人员能为 e、r、r⁺、q_cap、λ、d_ref、d、k、s_max、vⱼ、ρ、毛利等 ~12 组参数给出有来源的值。
- **Fails if**：参数表没有合理默认情景与来源标签，用户被迫瞎填；工具输出被当成预测。
- **Cheapest test**：P0 内置合成案例场景（第七节参数）作为可加载演示，验证「加载演示 → 改一个参数 → 重算」闭环即可用。
- **Kill criterion**：演示场景下用户无法在 30 分钟内完成一次完整比较 → 收窄首期为「演示 + 手工分桶」数据档，XLSX 导入降级。
- 注：提案已用 ParameterProfile + 证据状态 + 「不伪造置信区间」对此设防，实现不得绕过。

### 4. 黄金案例参数被偷偷固化成默认值（影响中 · 概率中 · 规约已明示禁止）

- **Claim**：q_cap=0.8、λ=2.2 等仅为演示参数（附录 A 明示非行业真值）。
- **Fails if**：实现把合成参数写成全局默认且界面不标来源，用户拿去当真实经营依据。
- **Cheapest test**：REVIEW 阶段检查所有默认参数对象的 evidence_status 是否为 synthetic_assumptions。

## What's Well-Reasoned

- **账本纪律是可证伪的**：互斥分支、概率合计=1、全部指标出自同一账本、4.6 拆解与 ΔΠ 对平——M01–M20 把这些写成了具体可测的行为，不是口号。
- **黄金数值精确可复现**（本次已验证到分）：验收有客观锚点，引擎正确性可机器判定。
- **允许「不发券」作为结论 + 四类结论而非冠军排序**，直接消除了「强行推荐」这一最常见的产品失败模式。
- **v1→v2 修订对照显示方案已自我纠错过一轮真实数学错误**（q×A 相关性、增量重复乘 hit、凑单失败缺流失分支、实付重复减券），公式设计比一般 PRD 严谨。
- **建设顺序明确**（先纯引擎+验收测试，再轻量界面），与 tracer-bullet 拆解天然契合。

## What I Couldn't Assess

- 真实经营数据下的参数可得性（无样本数据，提案自己也承认合成案例非真实验证）。
- 四页面 UI 的实际工作量上限（取决于是否复用本仓库现有工作台模式，PRD 决策）。
- 配套文件（自检 .py / 架构图 .png/.mmd）未随附件提供——不影响开发（黄金值在正文表中），但无法对照参考实现的代码组织。

## Verdict: **GO**

最高风险（公式-数值一致性）已被本次复算证伪；剩余风险通过拆解顺序、演示场景内置、证据状态标注控制。进入 PRD。
